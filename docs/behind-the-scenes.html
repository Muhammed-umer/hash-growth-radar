What happens in the background

One collection run of Hash Growth Radar, call by call, from the moment the timer fires to the moment a card appears on your screen.

Who is involved

Supabase databaseThe one place all data lives: the items, tags, runs, jobs and settings tables. Also the home of the timers.
Supabase CronA timer inside that database. At the set minute it sends one web request to the app. Nothing more.
The app on Vercelhash-growth-radar.vercel.app. Has three hidden routes for the timer (/api/cron/...) and the pages you open.
YouTube Data APIGoogle's official door. The app asks it for videos on a topic, then for the comments under each video.
GeminiGoogle's AI. The app sends it one comment at a time and gets back a small filled-in form (the tags).
YouOpen the dashboard whenever you like. Nothing waits for you; the list is already there.

The app never posts anything anywhere. Its only outgoing requests are reads from YouTube, tagging requests to Gemini, and reads and writes to its own database.

The three timers

TimerFires (India time)Request it sendsPurpose
radar_collectEvery 2 hours: 05:30, 07:30, 09:30 ...GET /api/cron/collectFetch new YouTube comments, filter, tag, score. This is the main one.
radar_processEvery hour, on the hourGET /api/cron/processSafety net. If the free AI limit was hit and some items are still "waiting for AI", tag them now.
radar_cleanupDaily, 08:30GET /api/cron/cleanupDelete every item older than 7 days, its tags, old run records and finished jobs. The privacy rule.

Every request carries the header Authorization: Bearer <CRON_SECRET>. The app compares it to its own copy of the secret in constant time and answers 401 to anything else. So nobody but the timer (or you, with the secret) can start a run.

The YouTube calls, exactly

Two endpoints of the YouTube Data API v3, both read-only, both with the API key from Google Cloud. Nothing else from Google is used.

Call 1 · search.list · one per topic · costs 1 of the 100 daily searches

GET https://www.googleapis.com/youtube/v3/search
    ?part=snippet
    &q=PCOS diet plan                 ← the topic
    &type=video
    &order=relevance
    &publishedAfter=2026-06-18T00:00:00Z   ← 90 days ago
    &maxResults=5                     ← "videos per topic" in Settings
    &relevanceLanguage=en
    &key=…

We keep from the answer: video id, video title, channel title. The channel becomes the "community" shown on the card, for example YouTube · Sonia Narang.

Call 2 · commentThreads.list · one per video · costs 1 unit of the 10,000 daily units

GET https://www.googleapis.com/youtube/v3/commentThreads
    ?part=snippet
    &videoId=…
    &order=time                        ← newest first
    &textFormat=plainText
    &maxResults=50                     ← "comments per video" in Settings
    &key=…

We keep from the answer: the comment id, the comment text, when it was posted, and its like count. Google also sends the commenter's display name and channel in that same answer. We do not read or store those fields. The card has no username, by design.

Before anything is shown: the four gates

A comment has to pass four gates to reach your list. Most fail at gate 2, which is the point: the AI only ever sees the few that might matter.

GateRuleWhoIf it fails
1 · Fresh and newPosted within the last 7 days, and not already in the table (same comment id).CodeNot stored at all.
2 · Keyword filterAt least 15 characters. Contains at least one word from the allow list (medicines like metformin, conditions like PCOS, tracking words like calorie or app, diet questions like "what to eat"). Contains no word from the block list (giveaway, crypto, hiring, meme...). For YouTube it must also look like a question: a "?" or a phrase like "can I", "should I", "which app". Whole words only, so "app" does not match "apple".CodeStored as filtered with the reason (too short, too old, blocked:crypto, no keyword, not a question). Shown in "Recently dropped" so you can see what the filter is doing.
3 · AI taggingGemini reads the text and fills the form: intent, conditions named, medicines named, competitor named, fit score 0 to 100, urgency, language, and whether this is someone we must not approach (dosage, diagnosis, emergency, eating disorder, mental health). If the answer is not valid, the app asks once more with the validation error attached; if it is still invalid, the job is retried later.AIIntent irrelevant becomes filtered (ai:irrelevant). "Do not approach" becomes not suitable. Both are visible in "Recently dropped".
4 · Score and rankScore = fit score + a bonus for the kind of question (medicine and food +15, asking for an app +10, competitor complaint +5) + a little for urgency, minus 2 per day of age up to 14. The Today page shows the 10 highest across platforms; each platform page shows its own 25.CodeEverything tagged stays visible on its platform page; only the order changes.

The AI call, exactly

One request to Gemini per item, model gemini-3.5-flash-lite on Google's free tier. Four API keys are rotated; a key that answers "slow down" is parked for a minute (an hour if Google says the daily quota is gone) and the next key is used. If all four are parked, the run stops and the hourly timer picks up the rest.

What is sent

  • Instructions (fixed): "You tag public posts for an internal tool... You fill in a fixed form about the QUESTION in the text. You never describe the person who wrote it." Then the definitions of each intent, how to score fit, and when to mark "do not approach".
  • The item: platform, community, title, and the text (cut at 4,000 characters). No username, no link.
  • A schema: the exact shape of the answer we accept, so the model must answer in that form and nothing else.

What comes back, for example

{
  "intent": "medicine_food_question",
  "conditions": ["type 2 diabetes"],
  "medicines": ["metformin"],
  "competitor": null,
  "fit_score": 92,
  "urgency": "low",
  "language": "en",
  "do_not_reply": false,
  "do_not_reply_reason": null,
  "summary": "Asks whether rice and roti are fine after starting metformin."
}

The answer is checked against the schema before it is stored (an out-of-range score or an unknown intent is rejected). The raw answer is kept in the tags row so a wrong tag can be inspected later. Google may use free-tier prompts to improve its products; the prompts contain public post text only.

What the screen reads

Opening a page runs a few database reads and nothing else:

  • Today: items with status tagged, highest score first, top 10, joined with their tags. Plus counts per status and per platform, and the job counts (waiting for AI, failed).
  • YouTube / Reddit page: the same list for that platform (top 25), the last 8 dropped items with their reason, the last 10 run records, and a check that the needed keys are present.
  • Settings: which environment variables are set (never their values), whether the AI provider is ready and how many keys are rotated, and the editable lists.

Pressing Approached or Skip changes that one item's status. Pasting a Reddit post runs gates 1 to 4 for that single post right away. Saving Settings writes the lists to the settings table. That is the complete list of things a page can change.

Local vs deployed: same data

Yes, npm run dev on your laptop shows exactly what the cron collected. There is one database, in Supabase. The timer wakes the deployed app, the deployed app writes to that database, and your local app reads from the same database because .env.local points at the same project. Nothing is cached on either side; every page load reads live.

The only thing the laptop cannot do is receive the timer's request, because Supabase cannot reach localhost. That does not matter: the deployed app receives it. If you ever want an extra run right now, call the route yourself with the secret and ?wait=1; it works against localhost and against the deployed URL alike.
