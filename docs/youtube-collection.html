What Google gives for free

The YouTube Data API v3 is Google's official, read-only door to public YouTube data. Any Google account can create an API key for it in the Google Cloud console. No card, no billing account, no approval. Verified on Google's quota page on 16 Sep 2026.

10,000 unitsper day, for everything except topic searches
100 searchesper day, a separate allowance just for topic searches
Resets dailyat midnight Pacific time (12:30 or 13:30 in India)

The search allowance is the tight one, which is why the tool spreads searches across the day instead of searching every topic every run. If a run ever exceeds it, YouTube answers "quotaExceeded", the run is recorded with that error, and the next run after midnight Pacific works again. Nothing else breaks.

What the timer does

A timer called radar_collect lives inside the Supabase database. Every 2 hours (05:30, 07:30, 09:30 ... India time) it does one thing: sends one web request to the app.

GET https://hash-growth-radar.vercel.app/api/cron/collect
Authorization: Bearer <CRON_SECRET>
  1. The app checks the secret and replies within a second: 202 {"ok":true,"started":true}. Anything without the right secret gets 401 and nothing runs.
  2. The app keeps working after replying, for up to 5 minutes. It opens a run record, reads the settings, picks this run's 4 topics, calls YouTube, filters, stores, tags, and closes the run record with the counts you see on the YouTube page.
  3. The timer does not wait for any of that. It has already moved on. Its own log (cron.job_run_details) only says "request sent, got 202".

Two other timers exist: radar_process every hour at :00 India time, which finishes any tagging that was left waiting because the free AI limit was hit, and radar_cleanup daily at 08:30, which deletes everything older than 7 days. Neither touches YouTube.

The two endpoints, exactly

YouTube has no "search comments by topic" call. So the app does it in two hops: find videos on the topic, then read the comments under each video.

Hop 1 · find videos on a topic · search.list

GET https://www.googleapis.com/youtube/v3/search
    ?part=snippet
    &q=PCOS diet plan                      ← this run's topic
    &type=video                            ← videos only, no channels or playlists
    &order=relevance                       ← YouTube's own ranking, i.e. the popular, well-matched ones
    &publishedAfter=2026-06-18T00:00:00Z   ← 90 days before today
    &maxResults=5                          ← "videos per topic"
    &relevanceLanguage=en
    &key=…

Kept from the answer: video id, video title, channel name. The channel becomes the "community" on the card (for example YouTube · Sonia Narang).

Hop 2 · read the newest comments · commentThreads.list, once per video

GET https://www.googleapis.com/youtube/v3/commentThreads
    ?part=snippet
    &videoId=…                             ← one of the videos from hop 1
    &order=time                            ← newest first
    &textFormat=plainText
    &maxResults=50                         ← "comments per video"
    &key=…

Kept from the answer: comment id, comment text, when it was posted, like count. Google also sends the commenter's display name in that answer; the app does not read it and there is no column to store it.

The keywords it searches

Nine topics, set in the code and editable on the Settings page. They are the q= of hop 1. YouTube searches video titles, descriptions and tags for them.

Six are condition diets, where comments like "I'm on metformin, can I follow this?" appear. Three are app reviews, where comments like "does it know Indian food?" appear. These topics find the videos; a second, separate keyword list (medicines, conditions, app words) is then applied to each comment before the AI sees it.

Does it search the same keywords every time?

No, not in one run. Yes, over a day. Each run searches 4 of the 9 topics, and each run continues from where the previous one stopped. The pattern for one day looks like this:

Result: every topic is searched 5 or 6 times a day, roughly every 4 hours, for 48 searches in total. The starting point is derived from the clock (the number of 2-hour windows since 1970), so it needs no memory and keeps moving even if a run is missed. Which run is "run 1" on a given day shifts slightly, but the pattern is always this one.

Does it fetch already-fetched data?

Yes, most of what a run fetches was already fetched before. That is expected and costs almost nothing. Two runs of "PCOS diet plan" four hours apart will return mostly the same 5 popular videos, and most of their 50 newest comments were already seen. What changes is the few comments posted in between, and those are exactly what we want.

The repeats are removed after fetching, in three layers:

  1. Older than 7 days. Any comment posted more than a week ago is dropped before storing. This is also the privacy rule: nothing older than a week exists in the database.
  2. Same comment id. Every YouTube comment has a permanent id. The items table refuses a second row with the same id, so a comment seen two hours ago is silently ignored now. Nothing is counted, filtered, or tagged twice.
  3. Same video, different run. Not a problem: reading a video's comments again costs 1 unit, and the new comments come first because of "newest first".

Where you can see it. On the YouTube page every run shows "fetched" and "new". The first run today showed fetched 117, new 117. A later run of the same topics will typically show fetched around 100, new under 10. The AI is called only for the "new" ones that also pass the keyword filter.

Is the search time-based?

Partly, and on purpose in two different ways:

  • Videos: last 90 days, ranked by relevance. Not "videos from the last 2 hours". A diet video keeps collecting question comments for weeks after it is published, and those comments are the audience. A brand-new video shows up once YouTube ranks it among the top 5 for the topic.
  • Comments: newest first, last 7 days kept. Each run reads the 50 most recent comments under each video, so the comments that arrived since the last run are always inside that window on any normal video.
  • Not used: a "since last run" cursor. The comment endpoint has no "only comments after time X" filter. Newest-first plus the id check does the same job with no state to keep.

Edge case: a viral video with more than 50 new comments in 2 hours would have some comments slip past the window. Raising "comments per video" to 100 covers it at no extra cost; the cap of 50 is a default, not a limit.
